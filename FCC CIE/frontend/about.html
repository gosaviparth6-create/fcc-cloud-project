📚 About This Project

Project Architecture & Syllabus Mapping

Every component of this project maps directly to a unit in the FCC CIE cloud computing syllabus. Here's how it all fits together.

🏗️ Architecture Overview
User Browser │ ├── Static Frontend (S3 Static Website / Netlify) │ ├── home.html · about.html · projects.html │ ├── index.html (Contact Form) │ └── admin.html (Admin Panel) │ ├── HTTPS → EC2 Instance (Amazon Linux 2023, t2.micro) │ ├── Nginx (reverse proxy, port 80/443) │ ├── Gunicorn (WSGI server, port 8000) │ └── Flask API (app.py) │ ├── /api/contact POST │ ├── /api/upload-doc POST → S3 Bucket │ ├── /api/admin/login POST │ └── /api/admin/* GET/DELETE (Bearer token) │ ├── S3 Bucket (PDF uploads, AES-256 encrypted) ├── PostgreSQL / SQLite (submission records) ├── IAM Role (EC2 → S3, least-privilege policy) ├── VPC (public subnet, SG: 22/80/443) └── CloudWatch (metrics, logs, billing alarm)

📋 Syllabus Unit Mapping

Unit Topic What Was Built / Demonstrated Evidence
Unit 1 Linux & Virtualization Provisioned EC2 (Amazon Linux 2023). Created system user portfolio, set file permissions (chmod 600), managed systemd service for Gunicorn. SSH key-pair auth. Used AI to troubleshoot Nginx/Gunicorn errors. deploy/portfolio.service
Unit 2 Networking Designed VPC with CIDR 10.0.0.0/16, public subnet 10.0.1.0/24, Internet Gateway, route table. Security Groups allow TCP 22 (SSH), 80 (HTTP), 443 (HTTPS). EC2 gets public IP; RDS in private subnet. deploy/nginx.conf
Unit 3 Cloud Fundamentals Compared public cloud (AWS) vs private vs hybrid. Mapped EC2 → IaaS, Render → PaaS, Gmail → SaaS. Applied AWS Shared Responsibility Model. Static frontend enables horizontal scaling. This page (about.html)
Unit 4 Core AWS Services EC2 (compute), S3 (static hosting + upload storage), IAM (least-privilege policy with S3 scoped to upload prefix), VPC (networking), CloudWatch (monitoring + logging), optionally RDS (PostgreSQL). deploy/iam-policy.json
Unit 5 DevOps, Git & Monitoring Git repo with main/dev branches, PR workflow. GitHub Actions CI/CD auto-syncs frontend/ to S3 on push to main. CloudWatch agent collects CPU/memory metrics. Billing alarm set at $5 threshold. .github/workflows/deploy.yml

🛡️ Shared Responsibility Model

AWS Manages
  • Physical hardware & data center security
  • Hypervisor (EC2 virtualization layer)
  • Global network infrastructure
  • S3 durability (11 nines) & replication
  • IAM service infrastructure
  • CloudWatch data plane
We Manage
  • OS patching (dnf update -y)
  • Security Group rules (ports 22/80/443 only)
  • IAM policy scoping (least privilege)
  • Application code & dependency updates
  • S3 bucket policy & encryption settings
  • SSH key management & rotation

⚖️ AWS vs Azure Service Comparison

Function AWS (Used Here) Azure Equivalent
Virtual Machine EC2 (t2.micro, Amazon Linux 2023) Azure Virtual Machine (B1s)
Object Storage S3 (static site + PDF uploads) Azure Blob Storage
Identity & Access IAM (users, roles, policies) Azure Active Directory + RBAC
Virtual Network VPC (subnets, SG, IGW) Azure Virtual Network (VNet)
Monitoring CloudWatch (metrics & logs) Azure Monitor + Log Analytics
CI/CD GitHub Actions → S3 sync Azure DevOps Pipelines
CDN / HTTPS CloudFront Azure CDN / Front Door
